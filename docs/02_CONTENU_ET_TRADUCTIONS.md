# 02 — Rédaction, contenus et traduction EN / FR

## 1. Contrat éditorial

**Langue de référence : anglais professionnel naturel** ; version française équivalente, non littérale. Éviter les phrases surjouées, les promesses exagérées, les statistiques inventées et les titres « senior/expert ». Décrire le **travail démontrable**. Séparer : ce qui est certain, ce qui est proposé comme formulation, ce qui reste à confirmer.

Le site doit dire explicitement « Software Developer » et « Full-stack Development · Web & Desktop Applications ». Le Hero graphique `IDEAS. CODE. IMPACT.` est un **slogan**, pas le métier. Celui-ci doit rester visible immédiatement.

- EN home title: `Software Developer | Full-stack, Web & Desktop` ; description: `Portfolio of a software developer working on full-stack web platforms and desktop business applications. View projects, experience and resume.`
- FR home title : `Développeur logiciel | Full-stack, Web & Desktop` ; description : `Portfolio d'un développeur logiciel spécialisé dans les plateformes web full-stack et les applications métier desktop. Projets, parcours et CV.`

- Pas de JSON-LD `Person` avec fausses données ; y ajouter URL et profils sociaux seulement après vérification.

## 10. Consignes de traduction et de ton

- Ne pas traduire `Software Developer` en anglais, mais `Développeur logiciel` en français.
- Ne jamais confondre portfolio et marketplace de services. Le positionnement recrutement domine.
- Phrase courte, verbe précis, ton simple, pas de jargon gratuit ; la créativité vient surtout du graphisme.
- Eviter les faux résultats : « improved performance by 70% », « thousands of users », « enterprise-grade », « led an engineering team » sont interdits sans preuve.
- Pour garder les chaînes cohérentes, fournir toutes les traductions dans un système de dictionnaires typés. Aucun placeholder `Lorem ipsum` en production.
